Almost every solution is this shape. The only things that change between them are the dials below.

The dials that set effort & price

  • Trigger — inbound event · scheduled · threshold-monitored
  • Decision classes / branches — none · one · several · multi-dimensional (e.g. language × type)
  • Systems touched — inbox · CRM · accounting · calendar · document store · data feed
  • Human gates — drafted reply held for approval · internal notify · money / publish sign-off
  • Fan-out — one input producing several drafts
Base — capture, route, file/log; little or no branching.
Base + triage — classify into a few classes + a drafted reply held for review.
Multi-branch — several decision points or checks before routing.

Two things that are always true

Approve-before-sendThe human stays in control. That's the product, not a caveat — and usually the reassurance that closes the trust gap.
Everything ends in a log / file / indexQuiet auditability by default — which sits well with Swiss/EU record-keeping habits.

Using this in discovery

  • Place the problem on the map, then sketch the primitive back to the client in their own words — fast, visible alignment.
  • Walk the five dials out loud; each answer is a scoping fact, not a guess (worksheet overleaf).
  • Point at the human gate explicitly — it's where "assistant, not autopilot" becomes concrete.
  • If a request doesn't fit the shape — autonomous, real-time, heavy data science, or a big one-off migration — say so early.
